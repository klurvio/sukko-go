# ADR-0007: The SDK targets Go 1.26 and adopts the platform's golangci-lint config

**Status**: Accepted
**Date**: 2026-08-23
**Ticket**: feat/go-sdk

## Context

The founding design set the module floor at Go 1.23 (picked for `iter.Seq` range-over-func and broad compatibility). But the whole Sukko project — the platform (`../sukko/ws/go.mod` is `go 1.26.1`) and this SDK — is developed and shipped on Go 1.26.*, and treating 1.23 as a live floor is a standing source of mistakes: it forbids `sync.WaitGroup.Go()` (1.25+), `new(expr)` (1.26), and `errors.AsType` (1.26), and it made a Phase-5 design review spend effort routing around primitives that are in fact available. Separately, the SDK's lint config was a hand-curated subset while the platform has a mature, constitution-aligned golangci-lint config; the two drifting means the SDK is held to a weaker bar than the code it ships alongside.

This decision was made by the project owner ("we use golang 1.26.\*"), so it is a product/stack decision recorded here, not a reversible engineering guess.

## Decision

**Go 1.26 is the version for the SDK.** `go.mod` declares `go 1.26.1`, matching the platform. This is not a low compatibility floor: the design may assume 1.26 features. `sync.WaitGroup.Go()` is the goroutine-launch primitive (so the epoch machinery of Phase 5 uses it, not `x/sync/errgroup` — which stays banned as a second runtime module under the one-dependency guard; first-error-wins is hand-rolled). This **supersedes the earlier 1.23-floor statements**, which are now stale on that point.

**The SDK adopts the platform's `.golangci.yaml`** so both lint to the same bar, with four documented deltas because the SDK is a pure client library, not a service:

1. `forbidigo` messages name `log/slog` (the SDK's logger), never zerolog (the platform's).
2. `protogetter` / `rowserrcheck` / `sqlclosecheck` / `paralleltest` are not enabled — no protobuf, no SQL, and `paralleltest` would demand `t.Parallel()` on the goleak- and shared-clock-based tests where it is forbidden.
3. Platform-only path exclusions (`cmd/`, `testutil/`, `*.pb.go`, `_shared_test.go`, `_serial_test.go`) are dropped; the generic `_test.go` exclusions stay and subsume the SDK's former test-scoped G304 carve-out.
4. A `testingcontext` exclusion in test files — the concurrency tests cancel their own contexts mid-test to drive discard/teardown paths, which `t.Context()` cannot express.

## Consequences

- CI must run on Go 1.26 (a matrix leg for 1.23–1.25 would now fail on 1.26-only features and must be dropped if it exists).
- External consumers need Go ≥ 1.26.1. Accepted: the whole project moves together, and the SDK is pre-v0.1.0.
- The richer linter set (wrapcheck at error severity, exhaustive, gocritic, modernize, perfsprint, wastedassign, revive rules) applies to all existing and future code; the one-time adoption fixed ~53 findings across Phases 1–4 (mostly British→US spellings, `fmt.Errorf`→`errors.New`, and modernizations), with two justified `//nolint`s (a total type assertion, a `slog.Handler` passthrough).
- `wg.Go()` simplifies Phase 5's epoch goroutines relative to the manual `Add`/`Done` the 1.23 floor would have forced.

## Alternatives rejected

- **Keep the 1.23 floor** — rejected: it does not match how the project is built or shipped, and it constrains the design away from primitives that are actually available, for a compatibility promise nobody is making pre-1.0.
- **Keep the SDK's hand-curated lint subset** — rejected: it holds the SDK to a weaker bar than the platform it ships with, and divergence is itself a maintenance cost. Adopting the platform config with a small set of documented, library-specific deltas is the lower-drift choice.
- **Adopt the platform config verbatim** — rejected: it bans the SDK's actual logger (slog) in favour of the platform's (zerolog), and enables `paralleltest`, which is incompatible with the goleak discipline the SDK's concurrency tests depend on.

# Feature Specification: Sukko Go SDK

**Branch**: `feat/go-sdk` (new sibling repo `sukko-go`)
**Created**: 2026-08-20
**Status**: Draft

## Context

Sukko ships two client SDKs today — TypeScript/JavaScript (`@sukko/sdk`, `../sukko-js`) and Python (`sukko`, `../sukko-py`). Its third audience is **Go backend services**: the platform itself is Go, and the highest-conviction server-side subscriber profile (market-data consumers, trading services, infra daemons) is heavily Go-native. For a *feed* product the "client" is frequently a long-running Go service, not a browser.

This SDK is a **new, standalone, open-source sibling repo** (`sukko-go`, module `github.com/klurvio/sukko-go`, import package `sukko`, MIT license — matching `sukko-js`/`sukko-py`).

**Design stance (important):** this SDK is built to the **authoritative AsyncAPI v1.4.0 + gateway OpenAPI contracts**, NOT to `@sukko/sdk`'s current behavior (which lags the contract: no back-pressure, no gap recovery, no automatic refresh — see the Python spec's Context). The **behavioral contract is identical to `sukko-py`** — the Python SDK is the reference implementation of the contract, and this spec is its Go-idiomatic translation. Where the two SDKs' *surfaces* differ, the difference is a deliberate idiom translation recorded in Resolved Decisions and the parity appendix (FR-001) — never a behavioral divergence.

**Authoritative contracts** (the SDK MUST derive its public types/behavior from these; it MUST NOT import, expose, or copy `ws/internal/shared/protocol` — being the same language as the platform makes this rule *more* important here, not less):
- WebSocket protocol: `ws/docs/asyncapi/client-ws.asyncapi.yaml` (**v1.4.0**, verified 2026-08-20)
- REST (publish, auth, SSE, push): `ws/docs/openapi/gateway.openapi.yaml`
- Channel contract: `{tenant}.{suffix}` (tenant = segment before first dot; suffix = opaque dotted remainder; ≥2 dot-separated parts)

**Delivery guarantee (stated plainly, §XV):** **at-least-once within the replay window on the Kafka backend** (reconnect-replay ≤100 msgs / 5s, live `replay`, `history`); **best-effort beyond the window and always on the Direct backend** — never implied gap-free. On Direct, every disconnect is an unrecoverable gap and the SDK emits a positive `PossibleGap` signal (FR-006).

## Resolved Decisions

- **Repo/module/package**: repo `sukko-go`; module `github.com/klurvio/sukko-go`; single import package `sukko` (subpackages only where forced, e.g. an internal wire package); **MIT** license; start `v0.1.0` (semver git tags; module path stays un-suffixed until a hypothetical v2). **Data-plane only** — subscribe / publish / auth / recovery / push-subscription-management; no provisioning/admin surface (that's `sukko-cli`, platform §XIV).
- **Go floor: 1.23**. The binding constraint is `iter.Seq`/range-over-func (1.23); `log/slog` (1.21) and generics (1.18) come free below it. Test matrix: 1.23 through the current release (1.23/1.24/1.25/1.26 at time of writing). The SDK does NOT track the platform's aggressive floor (Go 1.26) — a client library maximizes adoption; 1.23 is the newest version any needed feature requires.
- **NO sync/async split — one `Client`** (the headline structural delta from `sukko-py`). Python needed a `SyncSukkoClient` background-loop-thread wrapper because asyncio splits the world; Go's goroutine model makes the wrapper moot — every caller already has cheap concurrency, and `context.Context` replaces `CancelledError`/task-cancel semantics everywhere. **Dropped entirely**: Python Scenario 5 (sync wrapper), FR-009 (sync wrapper), the sync≡async parametrized-equivalence test burden (NFR-005), and SC-002's notebook criterion. The drop is recorded in the parity appendix (FR-001); nothing else about the behavior surface shrinks.
- **Delivery model: a single bounded in-band event channel, with an iterator convenience** (research.md D1). The primary surface is `client.Messages() <-chan Event` — `Event` is a small sealed union (interface with an unexported marker method) whose dominant concrete type is `*Message`; advisory/lifecycle events (`*PossibleGap`, forced-unsubscribe, publish acks/errors, recovery notices, state changes) flow **in-band on the same channel, in receive order**, so a `PossibleGap` arrives in-stream exactly where the potential loss sits relative to the data (the Python "single caller code path" property, §XV — one channel, one type-switch, no second channel whose overflow policy could silently drop exactly the signals that exist to prevent silent drops). A Go-1.23 **`Iter(ctx) iter.Seq[Event]`** wrapper is offered as range-over-func sugar over the same channel. **No callback registration surface** — centrifuge-go's synchronous-callback model documents its own deadlock hazard (blocking in a handler wedges the read loop) and is rejected as prior art; NATS's `ChanSubscribe` (channel buffer = pending limit, slow-consumer signaled at the boundary) and Polygon's `Output()` channel are the followed pattern.
- **Back-pressure is inherent — no capability split.** The read-pump performs a *blocking* send into the bounded channel: when the consumer lags, the pump stops reading the socket → the TCP window closes → the platform's own slow-client path engages (3 failed deliveries → close 1008 → reconnect+recover per FR-006). This is the Python bounded-queue + `can_pause_receive` model with the capability flag deleted — every Go WS transport can stop reading, so there is no capable/incapable branch (delta from the Python/JS transport-capability design, recorded in research.md D1). **Consequence, by design:** a fully-blocked read-pump also stops processing pongs and acks; the intended outcome of a persistently-slow consumer is the server's 1008, surfaced and recovered — never unbounded buffering, never silent drop.
- **Concurrency topology (the Go analog of sukko-py's per-epoch TaskGroup):** a single **supervisor goroutine** owns the connection lifecycle (connect → run epoch → backoff → reconnect). Each connection **epoch** gets its own derived context and its own goroutine set — read-pump, heartbeat ticker, recovery-deadline timers — launched under a per-epoch `errgroup`/`WaitGroup` and torn down/recreated wholesale on every reconnect (no goroutine survives its epoch). `Close(ctx)` cancels the root context, waits for the supervisor tree (bounded by ctx), then closes `Messages()` **from the sender side** (exactly-once, `sync.Once`); a caller draining the channel observes channel-close as the terminal signal. **No goroutine leaks** — asserted with `goleak` in every lifecycle test.
- **Runtime dependencies: exactly one** — `github.com/coder/websocket` (formerly `nhooyr.io/websocket`; context-native API, safe concurrent writes, actively maintained). REST publish + push + SSE ride stdlib `net/http`; the SSE `event:`/`id:`/`: keepalive` framing is parsed inline (no dep); JSON via stdlib `encoding/json` (union dispatch on the `type` field via a two-pass envelope decode). This is Go's near-zero-dep translation of Python's "minimal = 3". `gorilla/websocket` (what the *server* uses) is the documented fallback if `coder/websocket` proves limiting (research.md D2).
- **Errors: sentinels + typed structs + `errors.Is/As`** (FR-010). Sentinel `var Err…` values for expected conditions; typed structs (`*EditionRequiredError`, `*NotConnectedError`, `*RecoveryInterruptedError`, `*RateLimitError`, `*AuthError`, `*PublishError`, `*CloseError`…) carrying the contract's machine codes; every wrap uses `fmt.Errorf("op: %w", err)`. No raw `coder/websocket`/`net/http` error ever escapes the public surface un-wrapped, and **credentials are redacted from every error string** (§IX — Go's `url.Error` embeds the full request URL, so the query-param auth opt-in would otherwise leak the token).
- **Config: `NewClient(url string, opts ...Option) (*Client, error)` — functional options over an internal validated config.** The constructor validates and **fails fast** (platform §I spirit): invalid URL, empty credential set when auth is required, and the carried-over floor **`QueueSize ≥ HistoryLimit + MaxReplayMessages`** (sum, not max — a caller `history` and an automatic `replay` can be in flight concurrently; `MaxReplayMessages` = the contract bound 100) all return an error from `NewClient`, never a half-configured client. Options mirror sukko-py's knobs: credentials, `WithQueueSize`, `WithHistoryLimit` (default 100, tracking `WS_HISTORY_MAX_LIMIT`), `WithReconnect`/backoff params, `WithHeartbeatInterval`/pong timeout, `WithRefreshMinInterval` (default 30s), `WithReplayFloor` (default 10s/channel), `WithRecoveryDeadline` (default 10s = 2× server `WS_REPLAY_TIMEOUT`), `WithClientID`, `WithQueryParamAuth` (opt-in), `WithLogger(*slog.Logger)` (default discard), and the test seams `WithClock`/`WithRand`.
- **Determinism + race (the §VII/§VIII inversion vs the Python spec):** Go gets the real race detector — **`go test -race` is mandatory** in local dev and CI; a run without `-race` is not passing. **PLUS** the Python spec's deterministic-timing discipline carries over unchanged: every timing path (backoff/jitter, heartbeat, pong timeout, refresh floor, replay floor, recovery deadline) MUST go through an **injectable clock + injectable RNG seam** — never a real `time.Sleep`/`time.NewTimer` against the wall clock in tests. Python had only determinism (no race detector exists there); Go mandates **both**.
- **client_id provenance**: Go has no `localStorage`; the resume identity is **caller-supplied (`WithClientID`) or SDK-generated per-process** (documented: a fresh per-process id forfeits cross-restart replay unless the caller persists it) — parity with sukko-py Scenario 4.4.
- **`last_pos` key format — inherited pin, not reopened**: `last_pos`/`from_pos` maps are keyed by the **full tenant-prefixed channel** (e.g. `"sukko.BTC.trade"`), resolved from server source by sukko-py's T010b pin (`handleReconnect` → `ChannelTopic(channel)` keyed tenant-prefixed; a bare-suffix key silently replays nothing). The AsyncAPI's bare-suffix examples are the stale side (upstream filing #4, still unfixed — carried in Cross-Repo). The `pos` value is **opaque**: stored and echoed verbatim, never parsed.
- **Typed-payload decode helper: IN v1** (resolved 2026-08-20). The envelope keeps **`Data json.RawMessage`** (no forced decode on the hot path) AND v1 ships a package-level generic convenience decoder **`sukko.DataAs[T any](msg *Message) (T, error)`** that unmarshals `msg.Data` into a caller struct. Decode failures surface as a **typed `*PayloadDecodeError`** (carrying the channel, wrapping the underlying cause via `Unwrap`) — the public contract is the typed error, never a raw `encoding/json` error leak. This **commits a generics symbol to the public API surface** — the API-stability expectation is accepted and covered by semver discipline from `v0.1.0`. See FR-002a / SC-011 / NFR-005(o).
- **Observability hook: IN v1 — a pull-based `Stats()` snapshot** (resolved 2026-08-20). `client.Stats() Stats` returns a point-in-time counter snapshot: `MessagesReceived`, `Gaps` (wire `gap`s received), `PossibleGaps` (synthetic Direct-backend signals), `Replays` (replay requests issued), `Reconnects`, and `BackpressureBlocks` (read-pump blocked-on-full-channel episodes — there is no drops counter because drops are structurally impossible in this design). Counters are `atomic.Int64` increments (platform §VII — lock-free, off the hot path's critical section); **pull-based snapshot only, no callback firehose** — an event callback would re-introduce the centrifuge-go blocking hazard the delivery model rejects. `slog` remains the only push-style output. See FR-014 / SC-012 / NFR-005(p).

## User Scenarios

### Scenario 1 — Subscribe and consume a live feed with back-pressure (Priority: P1)
**Acceptance Criteria**:
1. **Given** a configured client, **When** `client.Connect(ctx)` then `client.Subscribe(ctx, channels)`, **Then** messages are consumed via `for ev := range client.Messages()` (or `for ev := range client.Iter(ctx)`), each `*Message` carrying channel + raw JSON payload + `Seq`/`Pos`.
2. **Given** a slow consumer, **When** the bounded delivery channel fills, **Then** the read-pump blocks (stops reading the socket → TCP back-pressure → the platform's own slow-client path) rather than buffering unboundedly, and **never silently drops** without an observable signal.
3. **Given** the platform disconnects a persistently-slow client (close **1008**), **When** it happens, **Then** the SDK surfaces it (typed `*CloseError`, in-band state event) and reconnects+recovers per FR-006.
4. **Given** a caller context cancelled mid-consumption, **When** `ctx` is done, **Then** `Iter(ctx)` returns promptly and `client.Messages()` remains valid for other consumers; cancelling the *client's* root context (via `Close`) closes the channel.

### Scenario 2 — Auth with JWT or API key, automatic refresh (Priority: P1)
**Acceptance Criteria**:
1. **Given** a JWT or an API key, **When** connecting, **Then** the credential is sent via **request headers** (`Authorization: Bearer` / `X-API-Key`) by default (query-param opt-in via `WithQueryParamAuth`), for both WS handshake and REST.
2. **Given** a long-lived connection, **When** the token nears expiry (from `auth_ack.exp`) OR the server sends `auth_error`, **Then** the SDK **automatically** refreshes via the `auth` message with a fresh token — **single-flight** (one in-flight refresh), respecting the **1-per-30s** floor with backoff (no auth_error→refresh loop). Token supply is a caller-provided `TokenSource` func (`func(ctx) (string, error)`) or a static token.
3. **Given** a refresh where the new JWT permits fewer channels, **When** it lands, **Then** still-permitted subscriptions are preserved and server-**forced** unsubscribes (`unsubscription_ack` with `forced: true`, `count` optional) are surfaced in-band — not a silent drop.
4. **Given** an API-key-only connection, **When** used, **Then** it is public-channel/receive-only (publish requires JWT; the SDK returns a typed error, not a raw 403).
5. **Given** an API-key connection that later supplies a JWT (**escalation**), **When** the `auth` succeeds, **Then** the SDK **re-issues `subscribe` for the newly-permitted channels** (delta only — the retained requested-but-not-granted set from FR-001a) — distinct from refresh (AC-3), which preserves subscriptions; escalation while offline defers to `UpdateToken` + reconnect.

### Scenario 3 — Publish (WS event-ack + synchronous REST) (Priority: P2)
**Acceptance Criteria**:
1. **Given** a connected client, **When** `client.Publish(ctx, channel, data)` over WS, **Then** it is fire-and-forget with `publish_ack`/`publish_error` surfaced as in-band events (the wire protocol has no per-call request id — no false request/response correlation).
2. **Given** a publish attempted while not `connected`, **When** called, **Then** it returns a typed `*NotConnectedError` immediately (`errors.Is(err, ErrNotConnected)`) — never a silent no-op.
3. **Given** a backend publisher, **When** it calls `client.RESTPublish(ctx, channel, data)`, **Then** it publishes over HTTP without a WebSocket and gets a genuine synchronous result. **Precondition**: REST publish is **Pro-gated** — a Community license yields a typed `*EditionRequiredError` (403 `EDITION_LIMIT`).

### Scenario 4 — Survive a disconnect with gap recovery (Priority: P1)
**Acceptance Criteria**:
1. **Given** reconnect enabled (default), **When** the connection drops, **Then** the SDK reconnects with **exponential backoff + jitter** (capped, clock/RNG-injectable) and sends `reconnect{client_id, last_pos}`; the server replays missed messages (bounded ≤100 msgs / 5s), surfaced through the same `Messages()` channel; `reconnect_ack`/`reconnect_error` are surfaced in-band.
2. **Given** an advisory `gap` on a live connection, **When** received, **Then** the SDK issues `replay{from_pos}`, consumes `replay_message`/`replay_complete`, and exposes **connection-scoped** `seq`-gap detection (`seq` starts at 1 per connection and **resets on every reconnect** — it is NOT per-channel; cross-connection continuity comes only from `pos`/`gap.last_pos`).
3. **Given** replay bounds are exceeded (`offset_out_of_range`/`replay_failed`/`replay_rate_limited`), **When** hit, **Then** the SDK surfaces a typed error and the caller can fall back to `History(ctx, channel, limit)` — the delivery guarantee is **at-least-once within the replay window, best-effort beyond**, stated plainly (§XV), never implied gap-free.
4. **Given** the Direct backend (`pos` absent, `reconnect_error: not_available`), **When** reconnecting, **Then** the SDK degrades to naive resubscribe **without a retry loop** and emits a **`*PossibleGap`** per resubscribed channel (FR-006).

### Scenario 5 — Build/parse channels + SSE transport (Priority: P2)
**Acceptance Criteria**:
1. `sukko.BuildChannel(tenant, suffix)` returns an error on empty/dotted tenant or empty suffix; `sukko.ParseChannel("acme.rooms.eng")` → `(Channel{Tenant:"acme", Suffix:"rooms.eng"}, nil)` (validation parity with `@sukko/sdk` `utils.ts` / sukko-py FR-008).
2. **Given** the SSE transport, **When** used, **Then** it subscribes via connect-time `channels`, resumes via `Last-Event-ID`, publishes over REST, and refreshes auth by reconnecting — its differing capabilities are explicit via `Capabilities()`, not hidden. It parses the gateway's SSE framing: `event: message` + `id: {sequence}` records **and periodic `: keepalive` comments** (used for idle-timeout detection); there is no `retry:` field or subprotocol. **Precondition**: SSE is **Pro-gated** (typed `*EditionRequiredError` on Community).

### Scenario 6 — Manage push subscriptions (Priority: P3)
**Acceptance Criteria**:
1. **Given** a backend with a mobile app's device token (FCM/APNs) or a browser-supplied Web Push subscription to register on a user's behalf, **When** `client.Push().Subscribe(ctx, PushSubscription{Platform: …, Channels: …, Token: … | Endpoint/P256dhKey/AuthSecret: …})`, **Then** it registers via the gateway and returns a `DeviceID int64`; `client.Push().Unsubscribe(ctx, deviceID)` removes it.
2. **Given** a client that must hand a VAPID public key to a web frontend, **When** `client.Push().VAPIDKey(ctx)`, **Then** it returns the key.
3. **Given** push is **Enterprise-gated** and the service may be unavailable, **When** a call hits the edition gate or an outage, **Then** the SDK returns a typed `*EditionRequiredError` (403) / push-unavailable error (503), not a raw `*url.Error`.
4. **Non-goal (explicit)**: this SDK does NOT *receive* push — a Go backend is not a push target (same rationale as sukko-py FR-013). There is no list-subscriptions endpoint (upstream filing #3, still open), so the caller persists returned `DeviceID`s.

### Dropped Scenario (deliberate, recorded)
Python's **Scenario 5 — sync wrapper / notebook use** has **no Go equivalent and is dropped**, not deferred: Go has no sync/async split to bridge. Its test-equivalence burden (sync≡async parametrized suite) is dropped with it; `goleak` + `-race` take its place as the lifecycle-correctness enforcement (NFR-005).

### Edge Cases
- **Close-code policy**: an explicit close-code → action table; the SDK tracks whether a close was **local- or remote-initiated** to disambiguate **4000** (AsyncAPI `force_disconnect`, remote) from the SDK's own client-initiated heartbeat-timeout close (upstream filing #1, still open — the SDK mitigates by tracking direction); terminal codes (auth-failed) do NOT trigger a tight reconnect loop; 1001 (going away) and 1008 (slow client) reconnect+recover; 1000 local = clean shutdown.
- **Cancellation / graceful close**: `Close(ctx)` cancels the root context, waits for the supervisor goroutine tree (`WaitGroup`/`errgroup`, bounded by the caller's ctx), closes `Messages()` exactly once from the sender side, and drains within a bounded timeout; a hung consumer cannot hang `Close` past its ctx deadline. `goleak` asserts zero leaked goroutines after every lifecycle test.
- **Heartbeat**: the app-level `heartbeat` message → `pong` (NOT WS ping/pong frames); missing `pong` within timeout → client-initiated close (distinct client code, direction-tracked) → reconnect+recover.
- **Payload limits differ per transport**: WS vs REST publish size limits come from `GATEWAY_MAX_PUBLISH_SIZE` (do not hardcode a literal — the OpenAPI still says 1MB while the Go `envDefault` and AsyncAPI say 64KB; upstream filing #2, still open; 64KB is authoritative). Oversized → typed error mapped per-transport (`message_too_large` / 413 `BODY_TOO_LARGE`).
- **Multiple goroutines consuming `Messages()` concurrently**: safe (channel receive is safe) but each event goes to exactly one receiver — documented; single consumer is the default pattern. `Iter(ctx)` is single-use-per-call and safe to abandon (range-over-func break returns cleanly).
- **JSON payloads**: `Message.Data` is `json.RawMessage` — the SDK never forces an allocation-heavy `map[string]any` decode on the hot path; callers decode into their own types, directly or via the `DataAs[T]` helper (FR-002a) — the SDK decodes a payload only when asked.

## Requirements

### Functional Requirements
- **FR-001 (client surface)**: One `Client` with `Connect(ctx)`, `Close(ctx)`, `Subscribe(ctx, channels)`, `Unsubscribe(ctx, channels)`, `Publish(ctx, channel, data)`, `RESTPublish(ctx, channel, data)`, `RefreshToken(ctx)`, `UpdateToken(token)` (set credential for next connect without sending `auth`), `History(ctx, channel, limit)`, `State() ConnectionState`, `Subscriptions() []string` (read-only snapshot), `Messages() <-chan Event`, `Iter(ctx) iter.Seq[Event]`, `Stats() Stats`, `Push() *PushManager`; plus the package-level generic `DataAs[T any](msg *Message) (T, error)` (FR-002a). **A parity table (appendix) maps each `sukko-py` public member → Go equivalent or dropped+why** (drops: `SyncSukkoClient`/`stream()` — no sync/async split; `async with` → `Connect`/`Close` + `context`; callbacks-as-sugar → not offered, channel/iterator only).
- **FR-001a (delivery)**: Events are delivered via a **single bounded channel** (`Messages()`, size `QueueSize`) carrying a sealed `Event` union — `*Message` plus in-band advisory/lifecycle events, in receive order. The read-pump send is **blocking** (back-pressure per Scenario 1.2); no unbounded buffering, no silent drop, no drop-on-overflow policy anywhere. On `subscription_ack`, the SDK MUST **diff requested-vs-`subscribed` channels**, surface any **not-granted** channels as a typed in-band event, and **retain the requested-but-not-granted set** (the SDK's model is *desired-vs-granted*; this retained set is the referent for the escalation delta in FR-005 and for subscription resume in FR-006) — the gateway *silently* drops unauthorized channels at subscribe, which contradicts the SDK's no-silent-drop stance unless surfaced.
- **FR-002 (server→client types)**: Typed Go structs for the **full AsyncAPI v1.4.0 clientReceive set**: `message`, `subscription_ack`, `unsubscription_ack` (optional `count`, `forced`), `publish_ack`, `publish_error` (11 codes), `reconnect_ack`, `reconnect_error` (3 codes), `pong`, `error` (8 codes), `subscribe_error`, `unsubscribe_error`, `auth_ack`, `auth_error` (5 codes), `history_complete`, `history_error` (9 codes), `gap`, `replay_message`, `replay_complete`. **Typing precision**: the wire `gap` model's `last_pos` is **required** (per the AsyncAPI `GapNotification` `required` set) — a malformed server `gap` missing `last_pos` is rejected at decode, not silently accepted. The Direct-backend "possible gap" signal is NOT a decoded wire `gap`; it is a **distinct SDK-emitted event type** (`PossibleGap`, `Channel`-only, no `LastPos`/`Pos`/`Seq` fields at all) so one value never means two things (§XV). Model `History bool` on the `Message` envelope (history-tagged records flow through `Messages()`); `truncated` on `history_complete`/`replay_complete` is omitempty — **absence decodes as `false`**; push `device_id` is **`int64`** (FR-013 callers persist an int). All int64 wire fields (`seq`, `ts`, `exp`) are Go `int64`.
- **FR-002a (typed-payload decode helper)**: A package-level generic **`DataAs[T any](msg *Message) (T, error)`** unmarshals `msg.Data` (`json.RawMessage`) into a caller type `T`. On decode failure it returns a **typed `*PayloadDecodeError`** carrying the message's `Channel` and wrapping the underlying `encoding/json` cause (reachable via `errors.As`/`Unwrap`, but never the bare public contract). `Message.Data` remains exposed as `json.RawMessage` — the helper is convenience, not the only path, and the SDK never decodes payloads it isn't asked to. This is the SDK's one committed generics symbol (API-stability note in Resolved Decisions).
- **FR-003 (client→server types)**: `subscribe` (incl. Pro-gated single-`channel`+`history` payload mode), `unsubscribe`, `publish`, `reconnect`, `heartbeat`, `auth`, `history`, `replay`. **Wire `type` consts MUST match the contract exactly** (`message` not `data`; `auth` not `auth_refresh`) — named constants, defined once (§I spirit).
- **FR-004 (transports)**: **WebSocket** (subscribe + publish; `coder/websocket`) and **SSE** (subscribe/receive over `net/http` streaming; publish via REST) behind a transport abstraction with explicit `Capabilities()` (`CanPublish`, `CanSubscribeLive`, `CanRefreshInPlace`). Reconnect/heartbeat/recovery live in the client, not the transport. **SSE is Pro-gated** — a Community license yields a typed `*EditionRequiredError` (403 `EDITION_LIMIT`), parity with FR-007's gating. **No `canPauseReceive` capability** — back-pressure is inherent in both Go transports (blocking send into the bounded channel stops the read loop); this is a documented delta from the Python/JS transport model.
- **FR-005 (auth)**: JWT + API-key for WS + REST, header-default (`WithQueryParamAuth` opt-in); **automatic single-flight token refresh** (proactive from `auth_ack.exp` — special-case `exp==0` = no-expiry, never schedule — + reactive on `auth_error`, 30s floor **configurable via `WithRefreshMinInterval`, default 30s**, backoff); `UpdateToken` vs `RefreshToken` distinct. Fresh tokens come from a caller-supplied `TokenSource` (func) or static credential — the SDK never mints tokens. The `auth` message is **dual-purpose**, and the SDK makes the mode-switch explicit off its own owned credential state (not runtime detection, §XV): on an API-key-only connection, providing a JWT **escalates** — and unlike refresh, escalation does NOT auto-subscribe previously-denied channels, so the SDK MUST re-issue `subscribe` for the **newly-permitted delta only** (the retained requested-but-not-granted set from FR-001a's grant diff; the re-subscribe's own `subscription_ack` then surfaces any still-denied channels). Escalation requires a live socket; when not `connected` it defers to `UpdateToken` + reconnect. Single-flight is enforced with `sync.Once`-per-cycle / mutex-guarded in-flight state — never two concurrent `auth` sends (`-race`-verified).
- **FR-006 (reconnect + recovery)**: Exponential backoff + jitter (configurable, clock/RNG-injectable), heartbeat + pong-timeout, subscription resume (desired set), **reconnect-with-replay** (`client_id` + per-channel `pos`), **advisory `gap` → live `replay`**, and **`history`** — the full recovery surface. Stated delivery guarantee per Scenario 4.3. Specifics (all behavioral clauses identical to sukko-py FR-006):
  - **Kafka-backend-only**: pos-anchored recovery (reconnect-replay, `replay`, `history`) requires the Kafka backend. On the Direct backend `pos` is **absent** and `reconnect_error: not_available` is returned — the SDK MUST handle absent `pos` and surface `not_available` as a **typed capability signal (not a retryable error)**, degrading to naive resubscribe.
  - **`last_pos` keying (pinned)**: per-channel `pos` tracked in a map keyed by the **full tenant-prefixed channel**; values opaque, echoed verbatim (Resolved Decisions).
  - **Live-replay rate floor**: 1 per 10s **per channel** (`WS_REPLAY_RATE_LIMIT_INTERVAL`) — the automatic `gap`→`replay` path MUST honor it (configurable `WithReplayFloor`), or it hits `replay_rate_limited`.
  - **History is a flagged `message`, not a distinct type**: history responses arrive as ordinary `Message` envelopes with `History: true`, terminated by `history_complete`; there is no `history_message` type. Subscribe-with-history requires Pro **and** the server toggle `WS_HISTORY_ENABLED=true` (else `history_disabled`).
  - **Recovery shares the delivery channel — do not let it self-sabotage**: replay (≤100) and history flow through the same bounded channel that drives back-pressure. `HistoryLimit` is a client-side construction knob (**default 100**, tracking `WS_HISTORY_MAX_LIMIT`; the SDK never *requests* more and rejects a larger history request client-side). The constructor MUST enforce **`QueueSize ≥ HistoryLimit + MaxReplayMessages`** (sum — a caller `history` and an automatic `replay` can be in flight concurrently; `MaxReplayMessages` = contract bound 100). A truncated recovery — a **missing `history_complete`/`replay_complete` within a client-side detection deadline** (`WithRecoveryDeadline`, **default 10s = 2× the server's `WS_REPLAY_TIMEOUT` of 5s**; clock-injectable), or a **1008/`replay_failed` mid-recovery** — MUST surface as a typed **`*RecoveryInterruptedError`**, never a bare disconnect (§III).
  - **Gap coalescing**: multiple `gap`s for the same channel within the 10s floor **coalesce** to a single `replay{from_pos = earliest un-recovered pos}` (new gaps during the wait only lower the watermark); a gap arriving **while a replay is in flight** is retained as un-recovered and, after `replay_complete`, drives the next replay (subject to the floor) — intervening gaps are never dropped and `replay_in_progress` stays near-unreachable. Surface `replay_rate_limited` only if a replay is still rejected. Never queue replays FIFO (unbounded lag) or silently drop gaps. The recovery state machine is a **single-owner goroutine communicating via channels** (platform §VII design preference) — no lock-ordering across the gap/replay/timer paths.
  - **Direct-backend delivery guarantee (explicit)**: on the Direct backend, delivery is **best-effort — any disconnect (including a back-pressure-induced 1008) is an unrecoverable gap** (real `gap`s are Kafka-only — `gap.last_pos` is a Kafka cursor). On Direct reconnect+resubscribe the SDK MUST emit a **positive "possible gap here" signal — a distinct `*PossibleGap` event (NOT a reused wire `gap`), one per resubscribed channel, `Channel` set, no pos/seq fields** — in-band on `Messages()`, so a single caller code path (type-switch + branch on `Channel`) sees a data-loss signal across both backends. This synthetic `PossibleGap` MUST NOT enter the coalescing/replay engine (no `last_pos` to anchor a replay). A surfaced *state transition* is not a surfaced *data-loss* signal (satisfies SC-008 at the reconnect boundary, not only at queue-fill).
- **FR-007 (REST publish)**: Synchronous `RESTPublish(ctx, …)` usable without a WS (Pro-gated; typed edition error), over stdlib `net/http` with a shared, configurable `*http.Client`.
- **FR-008 (channel helpers)**: `BuildChannel`/`ParseChannel` (+ a `Channel` value type) with `@sukko/sdk`/`sukko-py` validation semantics; errors, not panics.
- **FR-009 (concurrency & lifecycle)** *(replaces Python's sync-wrapper FR — see Dropped Scenario)*: the supervisor/epoch goroutine topology from Resolved Decisions is a requirement: all goroutines launched under tracked groups, per-epoch teardown before re-dial, `Close(ctx)` = cancel → wait (ctx-bounded) → sender-side channel close (exactly once) → drain; every public method is safe for concurrent use (`-race`-verified); zero goroutine leaks (`goleak`-verified). `context.Context` is the only cancellation mechanism — no stop-channels in the public API.
- **FR-010 (errors)**: Typed error surface mapping **every** contract error/close code: sentinels (`ErrNotConnected`, `ErrClosed`, `ErrEditionRequired`, `ErrNotAvailable`, …) matchable via `errors.Is`, typed structs via `errors.As` (`*EditionRequiredError`{Code, RequiredEdition}, `*NotConnectedError`, `*RecoveryInterruptedError`{Kind, Channel}, `*AuthError`{Code}, `*PublishError`{Code}, `*HistoryError`{Code}, `*ReplayError`{Code}, `*RateLimitError`{RetryAfter}, `*CloseError`{Code, Direction, Reason}, `*PayloadDecodeError`{Channel} — FR-002a). REST publish maps: 400 `INVALID_REQUEST`/`INVALID_CHANNEL`, 403 `FORBIDDEN` (distinct from `EDITION_LIMIT`), **409 `PUBLISH_NOT_ROUTABLE`** (Kafka-only), **413 `BODY_TOO_LARGE`**, 429 `RATE_LIMITED`, 503 `SERVICE_UNAVAILABLE` (retryable). Handshake **429 `TENANT_LIMIT_EXCEEDED`** (WS upgrade + SSE, tenant connection cap) is distinct in the reconnect policy — back off, do not hammer. (No `Retry-After` is declared on any gateway 429 — upstream filing #5, still open; `*RateLimitError.RetryAfter` is zero until it lands.) **§IX redaction**: credentials (JWT, API key, push `p256dh_key`/`auth_secret`) MUST be redacted from URLs, headers, and payloads in every returned error's `Error()` string and every log record (WS + REST + SSE) — `*url.Error`/`websocket.CloseError` wrap paths embed the full request URL, so the query-param auth opt-in would otherwise leak the token; typed wrapping alone is not redaction.
- **FR-011 (open-source repo)**: Public `sukko-go`, MIT, README quickstart, godoc on every exported symbol (clean pkg.go.dev render), CI (gofmt/goimports, `go vet`, golangci-lint, `go test -race` across the version matrix), semver git tags from `v0.1.0`.
- **FR-012 (contracts, not copies)**: Types/behavior derive from the AsyncAPI/OpenAPI contracts; MUST NOT import or copy `ws/internal/shared/protocol` (no cross-module dependency on the platform repo at all). Divergences from `sukko-py`'s surface (single client, channel delivery, one dep) MUST be documented as deliberate in the parity appendix.
- **FR-013 (push subscription management)**: A `client.Push()` manager wrapping the Enterprise-gated gateway endpoints — `Subscribe(ctx, PushSubscription{Platform web|android|ios, Channels, Token | Endpoint/P256dhKey/AuthSecret}) (int64, error)`, `Unsubscribe(ctx, deviceID int64)`, `VAPIDKey(ctx) (string, error)` — sharing the SDK's auth/token machinery, with typed edition/availability errors. **Explicitly NOT push *receive*** and **NOT operator config** (`/push/credentials`, `/push/channels` are sukko-cli's domain, §XIV). Caller persists `DeviceID` (no list endpoint exists — upstream filing #3).
- **FR-014 (observability — stats snapshot)**: `client.Stats() Stats` returns a **point-in-time snapshot** of monotonic counters: `MessagesReceived`, `Gaps`, `PossibleGaps`, `Replays`, `Reconnects`, `BackpressureBlocks`. Counters MUST be maintained with `atomic.Int64` (no locks on the delivery path — platform §VII/Message Pipeline Protection spirit: observation adds no forwarding latency); `Stats()` is safe for concurrent use and MUST NOT block or perturb delivery. **Pull-based only** — no stats callback/event-stream surface (a push hook would reintroduce the blocking-handler hazard FR-001a's delivery model rejects). There is deliberately **no drops counter**: the design makes drops structurally impossible (FR-001a); `BackpressureBlocks` is the observable stand-in. `slog` logging (Resolved Decisions) is the only push-style diagnostic output.

### Non-Functional Requirements
- **NFR-001 (one client, context-first)**: a single `Client` type; no sync/async duality anywhere; `context.Context` threads through every blocking public method; no API accepts a timeout parameter where a ctx suffices.
- **NFR-002 (typed & documented)**: every exported identifier has a godoc comment; the `Event` union is sealed (unexported marker method) so a caller type-switch is exhaustive over a known set; `golangci-lint` (incl. `revive`/`godot` doc checks) green.
- **NFR-003 (minimal deps)**: exactly **one runtime dependency** (`github.com/coder/websocket`); stdlib `net/http` + `encoding/json` for REST/SSE/codec; test-only deps allowed (`goleak`; optionally `go-cmp`). No frameworks, no logging deps (`log/slog` is stdlib).
- **NFR-004 (versions)**: Go **1.23+** (`go 1.23` directive); CI matrix 1.23 through the current release.
- **NFR-005 (test matrix)**: Explicit coverage — **one assertable test per** client→server message, per server→client event/error, per close code, plus heartbeat-timeout, close/drain, back-pressure blocking, reconnect-with-replay, live `gap`→`replay`, `history`. **Also required (the sukko-py post-clarify behaviors, translated)**: (a) **Direct-backend degrade** — `reconnect_error: not_available`/absent-`pos` degrades to resubscribe **without a retry loop**; (b) **subscribe-grant diff** — an ack granting a subset surfaces not-granted channels as a typed in-band event and retains the delta; (c) **escalation ≠ refresh** — one table-driven test: API-key→JWT escalation re-issues `subscribe` (newly-permitted delta) while refresh preserves subs; (d) `exp==0` arms no refresh timer; (e) `seq` resets on reconnect → no false gap; (f) handshake **429** backs off; (g) the **10s/channel replay floor** is honored + multiple gaps within it **coalesce** to one `replay`, and a gap arriving mid-replay drives a follow-up replay after `replay_complete`; (h) a recovery burst landing on a **partially-filled** channel engages back-pressure without deadlock or silent truncation, **and** `NewClient` **rejects `QueueSize` below the `HistoryLimit + MaxReplayMessages` floor**; (i) **§IX redaction** — in query-param AND header auth modes, a forced failure on each of WS/REST/SSE leaves the credential substring in **no** returned `Error()` string and **no** log record; (j) **`*RecoveryInterruptedError`** fires (never a bare disconnect) on both triggers — FakeServer omits `replay_complete` past the detection deadline, and FakeServer sends 1008 mid-replay; (k) **offline escalation** — supplying a JWT while not `connected` defers to `UpdateToken` (no `auth` sent) and re-subscribes the retained delta on the next connect; (l) **push-key redaction** — a forced push-call failure leaks the `p256dh_key`/`auth_secret` substrings in **no** error string/log; (m) **close/drain + leak-freedom** — `Close(ctx)` cancels the supervisor tree, waits ctx-bounded, closes `Messages()` exactly once, drains within the bound; **`goleak` asserts zero leaked goroutines after every lifecycle/reconnect/close test** (replaces Python's orphaned-task assertions); (n) **ctx cancellation** — a caller ctx cancelled mid-`Connect`/`Subscribe`/`Iter` returns promptly with `ctx.Err()` wrapped; (o) **`DataAs[T]` round-trip + typed decode error** — `DataAs[T]` decodes a typed payload round-trip, and a mismatched payload yields a `*PayloadDecodeError` (matchable via `errors.As`, carrying the channel) — never a bare `encoding/json` error as the returned type; (p) **stats counters are deterministic** — under FakeServer scenarios, a forced reconnect bumps `Reconnects`, a `gap`→`replay` cycle bumps `Gaps` and `Replays`, a Direct-degrade reconnect bumps `PossibleGaps`, and a filled-channel episode bumps `BackpressureBlocks`; `Stats()` read concurrently with delivery is `-race`-clean and never blocks the pump. **All tests run under `go test -race` — a run without `-race` is not passing (§VIII). Timing paths (backoff/jitter/heartbeat/timeouts/floors) MUST use the injectable clock + injectable RNG** — never real sleeps; determinism AND the race detector, both. Unit tests run against an in-process **FakeServer** (`httptest`-hosted WS endpoint speaking the contract; parity with sukko-py's FakeTransport/FakeServer); a **separate, opt-in** live-compose job covers **SC-001/003/004/005/007/009** smoke + wire-format (SC-008's deterministic back-pressure proof is FakeServer-only; live gets only a coarse slow-consumer smoke), **booted with an Enterprise license** (editions are cumulative — covers the Pro-gated publish/SSE suites and the Enterprise-gated push suite) and **`MESSAGE_BACKEND=kafka`** (SC-004's replay leg needs pos-recovery; a Direct stack cannot exercise it).
- **NFR-006 (docs)**: Copy-pasteable quickstart (connect → subscribe → `for range`), API reference via godoc, auth/channel/recovery/back-pressure guidance; the delivery-guarantee statement verbatim in the README.

### Key Entities
- **Client**: the single client type (no sync wrapper).
- **Transport**: WS / SSE adapter (`Open/Close/Send/State/Capabilities()`); recovery owned by the client.
- **ConnectionState**: **five** states — `connecting`, `connected`, `reconnecting`, `disconnected`, `error` (mirror `@sukko/sdk` `types.ts` / sukko-py).
- **Event (sealed union)**: `*Message` + in-band advisory/lifecycle events (`*PossibleGap`, forced-unsubscribe, grant-diff, publish ack/error, reconnect ack/error, recovery-interrupted notice, state change).
- **Messages**: full AsyncAPI v1.4.0 client↔server set (FR-002/FR-003).
- **Channel**: `{tenant}.{suffix}` value type + `BuildChannel`/`ParseChannel`.
- **Clock / Rand seams**: injectable time + RNG interfaces (test-only substitution; real implementations default).
- **Stats**: point-in-time counter snapshot (`MessagesReceived`, `Gaps`, `PossibleGaps`, `Replays`, `Reconnects`, `BackpressureBlocks`) — pull-based, atomic-backed (FR-014).

## Success Criteria
- **SC-001**: A ≤20-line example (`NewClient` → `Connect` → `Subscribe` → `for ev := range client.Messages()`) runs against a live stack and prints messages.
- **SC-002**: The full unit suite is green under `go test -race` across the entire version matrix (1.23→current), and `goleak` reports zero leaked goroutines after every lifecycle test — the Go substitute for Python's sync/notebook criterion.
- **SC-003**: **Every** AsyncAPI client-ws message type (full v1.4.0 set) has a typed SDK representation, round-trip verified against the contract (encode→decode equality on the wire shape).
- **SC-004**: After a forced disconnect, reconnect-with-replay recovers missed messages within the replay window with no consumer-code change; a live `gap` triggers `replay` and recovers.
- **SC-005**: Automatic token refresh rotates the token without dropping still-permitted subscriptions; forced unsubscribes are surfaced; refresh never exceeds 1/30s. **Escalation** (API-key→JWT) re-subscribes the newly-permitted delta — verified by one table-driven test discriminating refresh (subs persist) from escalation (re-subscribe).
- **SC-006**: CI green — gofmt/vet/golangci-lint, `-race` unit + (opt-in) integration, across the version matrix; `go get github.com/klurvio/sukko-go` resolves and imports cleanly; pkg.go.dev renders full docs.
- **SC-007**: A backend REST-publishes without a WebSocket (Pro license); Community gets a typed `*EditionRequiredError` matchable via `errors.As`.
- **SC-008**: Back-pressure is observable — a filled channel blocks the read-pump (deterministic test proves the socket read stops), no unbounded growth, no silent loss anywhere in the pipeline.
- **SC-009**: `Push().Subscribe/Unsubscribe/VAPIDKey` round-trip against the gateway (Enterprise license); Community/unavailable yields a typed error; push *receive* is absent by design.
- **SC-010**: On the **Direct backend**, `reconnect_error: not_available` (absent `pos`) degrades to naive resubscribe **without a retry loop**, and the reconnect emits `*PossibleGap` per channel — a slow-consumer→1008→reconnect on Direct never loses data *silently*. Deterministic FakeServer test.
- **SC-011**: `DataAs[T]` round-trips a typed payload (struct → publish → receive → `DataAs[T]` → equal struct) and a schema-mismatched payload returns a typed `*PayloadDecodeError` — no raw `encoding/json` error leaks as the returned error type. Deterministic test.
- **SC-012**: `Stats()` counters observably track behavior — a forced reconnect increments `Reconnects`, a `gap`→`replay` cycle increments `Gaps`/`Replays`, and a back-pressure episode increments `BackpressureBlocks` — verified deterministically under FakeServer, with `Stats()` reads concurrent to delivery `-race`-clean and non-blocking.

## Out of Scope
- Browser/mobile targets — served by `@sukko/sdk`.
- **Push *receive*** (Web Push, FCM/APNs) — not applicable to a Go backend; only subscription *management* (FR-013).
- **Operator push config** (`/push/credentials`, `/push/channels`) — sukko-cli's domain (§XIV).
- Provisioning/admin/tenant-management client — `sukko-cli`'s domain (§XIV); possible later optional package.
- A generated (AsyncAPI-codegen) type layer — hand-written structs + the SC-003 contract-coverage test (research.md D3).
- Framework integrations (no `net/http` middleware, no gRPC surface, no ORM-style layer) — the SDK is a client library, not a framework.
- Any change to the platform wire protocol or the contracts. **Exception**: the five upstream contract items from the Python pass (all **verified still-unfixed 2026-08-20**) remain filed upstream, not fixed here — see Cross-Repo.

## Cross-Repo Impact (§XVI)
- **sukko-docs**: the SDK-reference pipeline has a JS extractor (TypeDoc) and a Python extractor (griffe, `scripts/extract-py`) — there is **no Go extractor**. A Go SDK needs either a Go doc-reference extractor (driven by `go/doc` / `golang.org/x/tools/go/packages`, emitting the same MDX shape the other extractors produce, with the same loud-drop guard) or a hand-authored reference page as the stopgap — plus a guide page (quickstart/auth/recovery) and an **`llms.txt` entry** for every added page. **Coordinated when the SDK lands** (same logical change, may be a separate referenced PR).
- **tester/compose (integration)**: language-agnostic — the Go client connects as an ordinary WS/REST client; **no tester/compose code change**. The opt-in live integration job MUST boot with an **Enterprise license** (editions are cumulative — covers Pro-gated REST-publish/SSE and Enterprise-gated push) and **`MESSAGE_BACKEND=kafka`** (the SC-004 replay leg needs pos-recovery; Direct cannot exercise it).
- **ws/docs + gateway (upstream contract drift — carried forward, all five verified still open against the contracts on 2026-08-20)**: (1) close-code **4000** overlap (AsyncAPI table still lists only `force_disconnect`; the SDK mitigates by tracking close direction); (2) **`GATEWAY_MAX_PUBLISH_SIZE`** OpenAPI still says "default 1MB" vs the authoritative 64KB `envDefault` (the SDK treats 64KB as authoritative); (3) **missing list-push-subscriptions endpoint** (the SDK documents caller-persisted `DeviceID`s); (4) **`last_pos` bare-suffix examples** in the AsyncAPI — **resolved-by-pin for implementation** (sukko-py T010b pinned tenant-prefixed keys from server source; this SDK inherits the pin), the docs fix is still owed upstream; (5) **no `Retry-After` on any gateway 429** vs platform §IX (`*RateLimitError.RetryAfter` is plumbed and zero until it lands). These are `sukko` repo filings (docs-drift → `ws/docs` PR; gaps → gateway issues), already drafted in `sukko-py/specs/in-progress/feat/python-sdk/upstream-contract-filings.md` — this spec adds no new filings and re-files nothing.
- **sukko-js companion upgrade**: tracked from the Python spec's Cross-Repo section (its own spec/branch); nothing new added here. This SDK's single-client/inherent-back-pressure decisions are Go-specific and do NOT feed back into the TS transport-capability design.
- **sukko-py**: no change required; this spec cites its FR-006 clauses and T010b pin as the behavioral reference. If implementation uncovers a contract behavior where the two SDKs would diverge, the finding MUST be reconciled in both (platform §XVIII spirit applied across SDKs) — the shared 3-principle SDK constitution governs both repos.
